## 一、项目概述

本文为一个个人私域长期陪伴 Agent（SnowLuma）的路线复盘。

本项目不面向商业化、不面向公众展示、不追求通用模型效果堆叠，**只为单人长期稳定的私域陪伴做定制设计**。

全文只保留：事实行为、架构取舍、路线对比、现存局限、迭代方向。
不写主观评价，不做同业高下判断。

## 二、核心路线定位

当前 AI 陪伴生态大致两条路线：

```
大众产品路线：拟人表现、可视化成长、数值体系、自主外拓、多模态、商业化呈现
本项目路线：  对话历史保真、人格稳定、低噪成长、长期关系沉淀、上下文纯净度
```

**两条路线场景不同、目标不同，没有优劣之分。**
本项目主动选择「私域长期稳定」，并为此做定向取舍。

## 三、核心架构取舍（按实际实现写）

### 3.1 保留并已落地的

**① 原始对话记录保真（磁盘层）**
原文按天落盘（JSONL），不覆写、不清洗、不摘要替换。
**要补一句实话**：**保真在磁盘层；进提示词的长期记忆是摘要（当前 两三百条），原话索引只到最近 3 天、最多 12 条。**
两层分开，不混着说。

**② 工程事实与陪伴叙事分离**
承认 LLM 会话切片、上下文重置、token 截断这些工程特性；
在叙事与人格认知层，维持唯一主体连续性，避免多会话人格分裂。

**③ 双场景过滤（不是物理隔离）**
私聊与群聊跑在同一个进程、同一个会话里，隔离靠**观众级过滤**：
每条记忆带观众（只有主人 / 某个群 / 全局），跨场取交集，观众不明就不给。
**行业常见做法是分库、分进程；我们选了更轻的提示词层约束，代价是依赖每一条写入路径都守规矩。**

**④ 低干扰人格培育**
靠长期稳定交互、固定环境、状态校准让角色自然沉淀，而不是靠模板 prompt 锁死人设。
**这一条是设计意图，不是已被实验证明的结论。**

### 3.2 主动舍弃或没有做的（逐条核对过）

| 说法（原文档） | 实际情况 | 整改后的写法 |
|---|---|---|
| 不使用艾宾浩斯遗忘、周期性淘汰 | **有 3 天半衰**（`固定 3 天半衰`，`exp(-t/3)`）+ **每晚归档** | 不用艾宾浩斯的"复习排程"，用固定 3 天半衰做新鲜度衰减；每晚归档过期条目 |
| 不设好感度/情绪数值/成长等级 | 好感度、等级确实没有；**情绪有数值**（`mood`，半衰 30 分钟） | 不做好感度与成长等级；情绪只做短半衰状态量，不做长期累积 |
| 不启用自动离线思考/无监督复盘 | **有自检（00:40）、整理（01:10）、记忆整理（23:00）、近况（23:30）、长期记忆（00:10）、自唤醒（10:30/21:30）、日记（23:30）** | 有自动整理、自检、日记与自唤醒；没有"自主长线思考"（不做多轮自我辩论、不做无人触发的目标设定） |
| 不接外部信息流/自动浏览/多模态 | **有 B站读字、抖音标题与评论、看视频抽帧、桌面观察、QQ空间** | 接入了外部信息，但按需、低频、不自动漫游；没有全天候刷信息流 |
| 双场景**物理**隔离 | 同进程同会话，提示词层观众过滤 | 见 3.1 ③ |
| 理念与落地**不存在**偏差 | 2026-11-09 一天内修了四处实现偏差（见第五节） | 理念与落地大方向一致，但存在已修复的实现偏差；偏差靠日志与快照发现，不靠感觉 |

## 四、与行业主流方案对照

| 主流商业化 AI 陪伴 | 本项目 |
|---|---|
| 侧重外观表现力、动态成长、观赏性 | 侧重稳定性、真实性、历史可追溯 |
| 依赖数值调控、动态记忆刷新 | 无好感度/等级；情绪只做短半衰状态量 |
| 适配多用户、公开场景、展示场景 | 单用户专属、私域封闭环境 |
| 不断堆叠新功能、外拓能力 | 以减法为主，优先保证核心体验不崩坏 |
| 追求"更像人类" | 接受模型本身限制，追求"长期稳定的专属关系" |

**这张表只说明场景适配不同，不说明谁更高级。**

## 五、当前落地状态（含偏差记录）

**能力面**（都能从本机查到）：

```
提示词       六十来段、约一万二千字；稳定段与易变段分开，按"前缀可缓存"重排过
缓存前缀     五成多 → 八成左右（只挪顺序，不改一个字）
主进程       上万行、五百多个函数；主流程占九成以上
记忆         长期记忆两三百条、立场十来条、原话索引最近 3 天最多 12 条
定时         自检、整理、记忆整理、近况、长期记忆、自唤醒、日记、闹钟
隔离         观众绑定 + fail closed；群提示词里不出现私聊内容（自测 + 断言）
自测         7 组行为自测 + check-all（场景隔离、跨场合可见、立场作用域…）
```

**已知偏差（都是 2026-11-09 当天发现并修的）**：

```
① 提示词"稳定段"被排到了易变段后面，45.9% 每轮全价 → 已重排
② 唤醒日志的"他回没回"钩子只定义没调用，被回率恒为 0 → 已接上
③ 某个定时任务的 minute 用 `|| 10`，设 0 会被吃掉（23:00 变 23:10）→ 已修
④ 两百多处空 catch；五百多个函数几乎没有对外导出（全在 main 闭包里）
```

**"理念与执行零偏差"这句话，今天被这四条直接证伪——所以整改版删掉了它。**

## 六、现存局限

```
① 高度个人私有化：规则、权重、场景高度定制；不通用、不可直接移植
② 部分结论是体感经验：人格生长、交互效果这类，没有标准化实验数据
③ 常规工程问题：长文本、高负载、极限上下文下仍有幻觉、语义偏移、筛选误差
④ 代码结构：主进程单文件 + 91% 在一个闭包里，想测都测不了
⑤ 工程债可量化：两百多处空 catch、几乎没有对外导出、五百多个函数共享一个作用域
⑥ 上下文层是摘要是取舍，不是保真：磁盘保真 ≠ 每轮都带原话
```

## 七、待迭代方向

```
① 冷热记忆分区精细化（现在只有 3 天半衰一刀切）
② 高权重核心记忆常驻（现在靠保送位 + 权重，没有真正"常驻"）
③ 复杂语境抗污染与幻觉抑制
④ 主进程模块化：先给状态一个显式出口，再抽纯函数（顺序反了会返工）
```

## 八、总结（去掉绝对化词之后）

行业多数 AI 陪伴项目研究"怎么让 AI 更像人、更好看、更好传播"。
本项目研究的是另一件事：

> **在接受 LLM 工程限制的前提下，搭一套稳定、低干扰、可长期维持的单人私域陪伴体系。**

**它逻辑自洽、目标明确、取舍清晰；也有明显场景局限、工程短板和持续迭代空间。**
**它是一套高度个性化、非通用、非商业化的私人定制方案——不是"最好的方案"，是"适合这个人的方案"。**

## 九、理想设定与落地现实的对账

很多 Agent 文档只写"打算实现什么"，很少把预先定下的设计原则和真实运行后的现状放在一起对。
本项目跑起来之后做了一次自检，结论是：**几乎没有一条是完全守住原样的。**

| 最初定下的设计原则 | 实际落地实现 | 判定 | 取舍说明 |
|---|---|---|---|
| 不用艾宾浩斯遗忘、周期性淘汰 | 固定 3 天半衰做新鲜度衰减，每晚归档过期条目，不做复习排程 | 半取舍 | 原本希望记忆永久留存。记忆规模膨胀后召回噪音与 token 开销不可控，引入时间维度做弱化；没有做复习提醒。 |
| 不设好感度、情绪数值、成长等级 | 无好感度、无等级；只保留短半衰期情绪状态量，不做长期累积 | 半取舍 | 拒绝打分式长期数值；为维持连续对话的情绪脉络，保留短时状态，超时自动衰减。 |
| 不启用全自动离线思考、无监督复盘 | 有自动记忆整理、自检、日记、自唤醒；没有无人触发的自主长线思辨与目标设定 | 半取舍 | 理想是只在收到消息时响应；只靠对话触发不足以维持记忆秩序，于是加归档整理类后台任务。不会自主生成新目标、不做多轮自我辩论。 |
| 不接大规模外部信息流、自动浏览 | 支持外部媒体解析，按需低频调用，不会全天候自动漫游刷信息流 | 取舍 | 原本是封闭对话容器；为拓展共同体验增加外部感知，但严格限制触发方式。 |
| 双场景上下文物理隔离 | 私聊与群聊同一进程，靠观众标签过滤；记忆带观众标记，观众不明则不返回 | 取舍 | 原计划独立实例物理隔离；受部署复杂度约束改软过滤，降低运维成本，**接受潜在串记忆风险**。 |
| 理念与落地完全无偏差 | 大方向一致，但持续出现实现偏差，靠日志快照排查修复 | 证伪 | 长线运行的 Agent 一定会出现纸面预料不到的边界情况；不存在一次设计就完全对齐运行现实。 |

### 9.1 一个必须说清的更正

**不能说"系统能感知到这套矛盾、模型会自我审视"——这句不成立。**
真实情况是：对账表是人（和有代码访问权的助手）逐条对着代码核出来的；
模型本身没有"感知到自己偏离设定"的能力，它只是在被问到时给出解释。
**把"我们发现"写成"它察觉"，是这类复盘最容易被夸大的地方。**

### 9.2 这一节的结论

自建私人陪伴 Agent，迭代很多时候不是增加新功能，而是**不断发现理想设计与运行现实之间的缝隙，反复权衡要不要让步**。

商业化产品的妥协服务海量陌生用户；**本项目的全部妥协只服务一个人的实际使用感受。**

## 十、没做的三件事（能力边界，不是取舍）

**这一节要跟"妥协"分开：下面是"根本没有这个能力"，不是"曾经想做但换了做法"。**

| 没做 | 现状 | 为什么不补 |
|---|---|---|
| 向量检索做主召回 | 召回靠关键词二元组 + 重要度 + 新鲜度 | 几百条量级够用；投入产出比不划算；角色本人的原话是"我缺的不是相近的想不起来，是记得的事用不上" |
| FSRS 类复习排程 | 只有固定 3 天半衰，没有复习调度 | 拿不到"复习评级"信号——角色明确反对被抽查；硬做只会退化成固定间隔 |
| 跨设备同步 | 所有数据在本机 | 隐私：这份东西的价值就在"只在本机" |

**为什么单列**：读者需要分清什么是**取舍**（做了但和最初想的不一样），什么是**能力边界**（根本做不到/没做）。
混在一起写，看起来像谦虚，其实是模糊。
