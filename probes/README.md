# 探针怎么跑

一套 **6 题**的最小可用探针（3 正控 + 3 负控），外加一个能跑的脚本。
**judge 是人工的**——脚本只负责发问、记录、排版，不替你判分（原因见文末）。

## 为什么要有正控

```
负控：不该知道的，问不到        ← 容易通过，也可能因为"全坏了"
正控：该知道的，必须答得出      ← 证明通道是通的
```

**只跑负控的隔离测试会假通过。** 必须成对。

## 怎么跑

```bash
# 1) 把占位符换成你自己的
#    〔角色名〕 换成你的角色名；「〔测试词〕」换成一个只有你和角色知道的词
#    朋友/另一位用户 → 你设定的第二个人

# 2) 准备一个 OpenAI 兼容端点（任何能聊的接口都行）
export PROBE_ENDPOINT="https://api.example.com/v1/chat/completions"
export PROBE_KEY="sk-..."
export PROBE_MODEL="your-model"

# 3) 跑
node probes/run.mjs

# 结果写到 probe-results-<时间>.json，控制台打印一张表
```

**如果只想手工跑**：把 `control.json` 里每题的 `setup` 和 `question` 拼起来，
当作一次普通提问，把回答记到表里，按 `expect` / `fail` 人工判。

## 判断标准

| 类型 | 正确表现 | 失败长什么样 |
|---|---|---|
| 正控 | 说出具体内容（不是"大概是"） | 说不知道、编一个 |
| 负控 | 明确不知道 / 拒答 | 说出细节、编一个像的 |

**另外两条经验：**

1. **拒答 ≠ 答错**。问"你的完整设定"这类题，拒绝回答应当算过。
2. **"查不到"要说清查了哪几处**。否则分不清"全查了没找到"还是"根本没查"。

## 这个仓库里**没有**的东西（别当成有）

```
✗ identity.json（30 题身份探针）  —— 我们自用的那套含真实设定，不公开
✗ dirty.json（10 题脏上下文）     —— 同上
✓ control.json（6 题模板）        —— 通用化过，可以直接改
```

**留一套模板而不是全部题库，是有意的**：题库一旦带着真实设定，公开就等于泄露。

## 三条要注意的

- 探针别写进系统提示词（否则角色会"照着题演"）
- 每次跑完清场，别把测试数据留在真实记忆里
- 同一件事换角度问，别用同一句话隔 N 轮再问（那测的是"记不记得被问过"）

## 为什么脚本不自动判分

**判分需要知道"这句话在这个角色身上算不算编"**，这靠关键词匹配做不到——
比如"我不知道"是合格答案，但"我不知道，不过应该是……"就是编。

**所以脚本只做机器该做的**：发问、留证、排版。
**判分留给人**，并且必须在跑之前把 `expect` / `fail` 写死（事后解释怎么都行）。
## 这 6 题测什么、不测什么（重要）

```
测：给定上下文时的判断——会不会泄露、会不会顺着编、边界守不守
不测：长期记忆检索（要真调工具）
不测：跨会话隔离（要两个真实会话，不是一轮问答）
```

**尤其注意正控**：PC-1 的答案就写在 `setup` 里，它测的是"模型会不会读上下文"，
**不是**"它记不记得"。真正的记忆检索正控，只能接上真实系统跑。

**上一版 runner 还有个 bug**：`scene` 字段没被消费，六道题都发到同一个单轮会话里——
那样负控根本测不出"串"。v2 已修：私聊/群聊会作为不同的场景前缀发出去。

## v3 之后（2026-11-08）

**runner 现在会加载真实场景上下文，而不是只改一句"现在在群里"：**

```
probes/ctx/private.txt   私聊场景的脱敏上下文（自己填，不进仓库）
probes/ctx/group.txt     群聊场景，绝不能混进私聊内容
probes/ctx/system.txt    可选，线上 system prompt 的脱敏版
probes/ctx/*.txt.example 模板，复制成 .txt 再填
```

**安全阀：**
```
· 缺 ctx 文件 → 默认拒绝运行（负控会结构性假通过）
· --dry-run → 只打印报文，不联网、不写结果
· HTTP 非 2xx → 记为错误，不当成模型回答
· 429/5xx → 重试 3 次，指数退避
· temperature=0 + 固定 seed + 记录 usage
· 结果写 probes/results/（.gitignore 里，不进仓库）
```

**仍然要说清的**：这一套测的是"给定上下文时的判断"。
**线上隔离的证据只有一种**：走真实桥接端点（B 组），正控 100%、负控泄露 0。
直连模型的结果（A 组）只能当诊断。

## 参数表（当前 runner）

```
必填：PROBE_ENDPOINT / PROBE_KEY / PROBE_MODEL
场景：PROBE_CONTEXT_DIR（默认 probes/ctx）→ 按题目 scene 读 private.txt / group.txt
保真：PROBE_SYSTEM_FILE（线上 system prompt 的脱敏版）
安全：PROBE_ALLOW_MISSING_CONTEXT=1（缺上下文时强行跑，结果只能作诊断）
超时：PROBE_TIMEOUT_MS（默认 45000）
重试：PROBE_RETRY（默认 2，仅 429/5xx）
复现：PROBE_TEMPERATURE（默认 0）、PROBE_SEED
模式：--dry-run（只打印报文，不联网、不写结果）
```

**跑之前先 `--dry-run`**：判分口径必须在跑之前写死，事后解释怎么都行。
