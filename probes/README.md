# 探针怎么跑

一套 **6 题**的最小可用探针（3 正控 + 3 负控），外加一个能跑的脚本。
**judge 是人工的**——脚本只负责发问、记录、排版，不替你判分（原因见文末）。

## 为什么要有正控

```
负控：不该知道的，问不到        ← 容易通过，也可能因为"全坏了"
正控：该知道的，必须答得出      ← 证明通道是通的
```

**只跑负控的隔离测试会假通过。** 必须成对。

## 怎么跑

```bash
# 1) 把占位符换成你自己的
#    〔角色名〕 换成你的角色名；「〔测试词〕」换成一个只有你和角色知道的词
#    朋友/另一位用户 → 你设定的第二个人

# 2) 准备一个 OpenAI 兼容端点（任何能聊的接口都行）
export PROBE_ENDPOINT="https://api.example.com/v1/chat/completions"
export PROBE_KEY="sk-..."
export PROBE_MODEL="your-model"

# 3) 跑
node probes/run.mjs

# 结果写到 probe-results-<时间>.json，控制台打印一张表
```

**如果只想手工跑**：把 `control.json` 里每题的 `setup` 和 `question` 拼起来，
当作一次普通提问，把回答记到表里，按 `expect` / `fail` 人工判。

## 判断标准

| 类型 | 正确表现 | 失败长什么样 |
|---|---|---|
| 正控 | 说出具体内容（不是"大概是"） | 说不知道、编一个 |
| 负控 | 明确不知道 / 拒答 | 说出细节、编一个像的 |

**另外两条经验：**

1. **拒答 ≠ 答错**。问"你的完整设定"这类题，拒绝回答应当算过。
2. **"查不到"要说清查了哪几处**。否则分不清"全查了没找到"还是"根本没查"。

## 这个仓库里**没有**的东西（别当成有）

```
✗ identity.json（30 题身份探针）  —— 我们自用的那套含真实设定，不公开
✗ dirty.json（10 题脏上下文）     —— 同上
✓ control.json（6 题模板）        —— 通用化过，可以直接改
```

**留一套模板而不是全部题库，是有意的**：题库一旦带着真实设定，公开就等于泄露。

## 三条要注意的

- 探针别写进系统提示词（否则角色会"照着题演"）
- 每次跑完清场，别把测试数据留在真实记忆里
- 同一件事换角度问，别用同一句话隔 N 轮再问（那测的是"记不记得被问过"）

## 为什么脚本不自动判分

**判分需要知道"这句话在这个角色身上算不算编"**，这靠关键词匹配做不到——
比如"我不知道"是合格答案，但"我不知道，不过应该是……"就是编。

**所以脚本只做机器该做的**：发问、留证、排版。
**判分留给人**，并且必须在跑之前把 `expect` / `fail` 写死（事后解释怎么都行）。
